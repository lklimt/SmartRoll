# SmartRoll – Home Assistant / MQTT integration

## Integration method

SmartRoll uses the existing Mosquitto MQTT broker. Home Assistant consumes MQTT discovery messages generated by the ESP32.

Home Assistant supports MQTT discovery and MQTT cover entities. See the official MQTT documentation:

https://www.home-assistant.io/integrations/mqtt/

## Broker

The ESP32 must reach the Mosquitto broker over TCP port **1883**.

For the dedicated IoT network, the preferred firewall policy is:

```text
IoT ESP32  ───── TCP/1883 ─────>  MQTT broker on NAS/HA
```

Other IoT-to-LAN access should remain blocked unless required by another service.

No inbound connection from Home Assistant to the ESP32 is required for control: HA publishes the command through MQTT and the ESP32 subscribes to its command topic.

## Topics

Device ID:

```text
smartroll_01
```

Base topic:

```text
smartroll/smartroll_01
```

### Command

```text
smartroll/smartroll_01/cover/command
```

Payloads:

```text
UP
DOWN
STOP
```

### Availability

```text
smartroll/smartroll_01/availability
```

Payloads:

```text
online
offline
```

### Combined state

```text
smartroll/smartroll_01/state
```

Example:

```json
{
  "hall_a": 1,
  "hall_b": 1,
  "position": 0,
  "cw": 120,
  "ccw": 120,
  "invalid": 0,
  "transitions": 240,
  "lux": 235.42,
  "temperature": 24.31,
  "pir": 0,
  "rssi": -57
}
```

### Cover state

```text
smartroll/smartroll_01/cover/state
```

Possible values used by the firmware:

```text
OPENING
CLOSING
STOPPED
```

Absolute OPEN/CLOSED position is intentionally not implemented yet because the Hall-count-to-blind-position calibration remains OPEN.

### Direction

```text
smartroll/smartroll_01/direction/state
```

Values:

```text
CW
CCW
UNKNOWN
```

### Firmware

```text
smartroll/smartroll_01/firmware/state
```

## MQTT discovery

The ESP32 publishes retained discovery configuration under:

```text
homeassistant/cover/smartroll_01/cover/config
homeassistant/sensor/smartroll_01/temperature/config
homeassistant/sensor/smartroll_01/illuminance/config
homeassistant/sensor/smartroll_01/hall_position/config
homeassistant/sensor/smartroll_01/hall_invalid/config
homeassistant/sensor/smartroll_01/wifi_rssi/config
homeassistant/sensor/smartroll_01/direction/config
homeassistant/sensor/smartroll_01/firmware/config
homeassistant/binary_sensor/smartroll_01/pir/config
```

Home Assistant should therefore create one SmartRoll device automatically after MQTT connectivity is established.

## First HA test

1. Flash Test 6 firmware with correct local Wi-Fi/MQTT credentials.
2. Open Arduino IDE Serial Monitor at 115200 Bd.
3. Verify:

```text
Wi-Fi: connected
MQTT: connected
BH1750: OK
```

4. In Home Assistant open **Settings → Devices & services → MQTT**.
5. Verify the SmartRoll device and entities appear.
6. Use the cover entity to send UP, STOP and DOWN.
7. Confirm the physical blind moves.
8. Confirm Hall counters change while the RF command is active.
9. Confirm temperature, illuminance and PIR entities update.

## Troubleshooting across the IoT VLAN

If Wi-Fi connects but MQTT does not:

1. Verify the MQTT broker IP in the firmware.
2. Verify MQTT username/password.
3. Verify TCP 1883 is allowed from the ESP32 IoT network to the broker.
4. Verify the broker is listening on the expected interface.
5. Check Mosquitto logs.
6. Test the broker from another host in the same IoT network with an MQTT client.

No mDNS dependency is required for MQTT operation when the broker is configured by IP address.
