# SmartRoll – Home Assistant / MQTT integration

## Integration method

SmartRoll uses the existing Mosquitto MQTT broker. Home Assistant consumes MQTT discovery messages generated by the ESP32.

This is intentional: the ESP32 keeps the validated custom ERTE RF implementation and Hall quadrature decoder, while MQTT provides the integration layer to Home Assistant.

## Network

The ESP32 connects to the dedicated IoT Wi-Fi network through the MikroTik IoT AP.

The preferred firewall path is:

```text
ESP32 / IoT Wi-Fi ── TCP/1883 ──> Mosquitto on Synology NAS
```

No inbound connection from Home Assistant to the ESP32 is required for normal control.

Device ID:

Base:

Command:

```text
smartroll/smartroll_01/cover/command
```

Payloads:

```text
UP
DOWN
STOP
```

Availability:

```text
smartroll/smartroll_01/availability
```

Payloads:

```text
online
offline
```

State:

```text
smartroll/smartroll_01/state
```

Example:

```json
{
  "hall_a": 1,
  "hall_b": 1,
  "position": 0,
  "cw": 120,
  "ccw": 120,
  "invalid": 0,
  "transitions": 240,
  "direction": "UNKNOWN",
  "lux": 235.42,
  "temperature": 24.31,
  "rssi": -57

```

Cover state:

```text
smartroll/smartroll_01/cover/state
```

Possible values:

```text
OPENING
CLOSING
STOPPED
```

Absolute OPEN/CLOSED position and percentage are intentionally not implemented yet. The Hall-count-to-blind-position calibration remains open.

## Home Assistant entities

MQTT Discovery creates one SmartRoll device with:

- cover – UP / DOWN / STOP
- temperature
- illuminance
- Hall direction
- relative Hall position/count
- invalid Hall transition counter
- Wi-Fi RSSI
- firmware version

## First HA test

1. Flash Test 6 with local Wi-Fi/MQTT credentials.
2. Open Arduino IDE Serial Monitor at 115200 Bd.
3. Verify Wi-Fi and MQTT connection.
4. In Home Assistant open the MQTT integration.
5. Verify the SmartRoll device and entities appear.
6. Send UP, STOP and DOWN from the cover entity.
7. Confirm RF commands are received by the laboratory test receiver/fixture.
8. Confirm Hall counters/direction change during movement.
9. Confirm temperature and illuminance update.

## Troubleshooting

If Wi-Fi connects but MQTT does not:

1. Verify MQTT broker IP.
2. Verify MQTT username/password.
3. Verify IoT → NAS/Mosquitto TCP 1883 is permitted by the MikroTik firewall.
4. Verify Mosquitto is listening on the required interface.
5. Check Mosquitto logs.

No mDNS dependency is required when the broker is configured by IP address.
